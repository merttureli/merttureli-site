# 3D look system

Every 3D thing on both sites follows these rules so a new model looks like it belongs. Values are copied from the live code; the file named in each row is the source of truth. To bring a CAD model in, see [cad-import.md](../recipes/cad-import.md).

## Units, axes, origin

| Rule | Value |
|---|---|
| Units | meters in every runtime file. CAD is mm; the importer divides by 1000 |
| Up | +Y. A Z-up STEP needs `--up z` (turns (x, y, z) into (x, z, -y)) |
| Camera | looks down -Z, so +Z faces the viewer |
| Origin, showreel guests | the top surface center of the main plate or the footprint center (`coaster.js`: plate top at 0, shell down to y = -0.0453). Map `origin`: `top`, `bottom`, `center`, `keep` |
| Origin, CHARGER | CAD origin kept (`origin: keep`): the airframe runs y = -0.5707 .. 0.5707 |
| Part pivot | each part's Group sits at its bounds center, so it spins about itself when it flies; `setPivot()` moves it to a hinge |
| Handedness | right-handed (three.js) |

## Renderer and camera (`next/js/showreel/engine.js`)

| Setting | Value |
|---|---|
| Renderer | `WebGLRenderer({ antialias: true, alpha: true, powerPreference: 'low-power' })`, transparent clear |
| Pixel ratio | `min(devicePixelRatio, 1.75)` |
| Color | `outputColorSpace = SRGBColorSpace`, no tone mapping (three default `NoToneMapping`), exposure 1 |
| Camera | `PerspectiveCamera(24, aspect, 0.05, 30)` at z = 2.2 |
| Rocket framing | `hero3d.js` `LAYOUTS`: land `fov 24, dist 2.2, tiltZ 1.16, tiltX .16, roll .34`; port `dist 3.0, tiltZ .6` |
| Shadows | none from lights. Contact shadows are soft decals (`coaster.js` baked shadow at opacity .55; `index.js` `contactShadow()`) |

Environment: `createStudioEnvironment()` renders once into a PMREM (blur .035): a sphere graded `#f4f2ee` top, `#d9dadd` middle, `#6f737a` bottom, a key softbox (6 x 4 at (-4, 6, 5), gain 3.2), a rim strip (1.4 x 7 at (6, 3, -5), gain 2.2) and a fill card (5 x 2 at (5, -1, 4), gain .9). | CHARGER explorer interior (`charger-explorer`) | 22,772 | 17 parts | 307 KB bin (+ the hero's 428 KB, already loaded) |
| **New showreel guest (CAD)** | **50,000 max, aim 20,000** | **24 parts max** | **aim under 500 KB** |

`tools/cad.py import` prints the total and warns over 50,000 triangles or 24 parts with the three heaviest parts. Ways down, in order: skip parts nobody sees (`"skip": true`), merge small parts into one name (one Group, one mesh per material), coarser rule for heavy parts (`"deflection": 0.1, "angle": 0.8`), `--quality low`.

Showreel quality is `low` when the viewport is under 760 px wide or the device has 4 cores or fewer or 4 GB or less (`index.js`). A CAD guest can ship a second file for that case: import again with `--name <name>-low --quality low` and pick it in the actor by `quality`.

## Motor flame (hero intro)

`next/js/showreel/flame.js`, driven by `hero3d.js` `createIntro()`. CHARGER flies an AeroTech G77R-7 single use
(29 x 124 mm, Redline propellant). The flame keeps the CAD look: three nested soft lathe cones (premultiplied
alpha, soft silhouettes, a slow sine flicker) and one glow card; no photo textures, no particles.

| What | Value | Source |
|---|---|---|
| Thrust | RASP curve, 66 N at .06 s, 99 N peak at .64 s, burnout 1.277 s, ~80 N average; time-scaled to the 1.25 s fly-in | thrustcurve.org G77R/L (same samples as `vx/js/data/motor-g77r.js` on main); AeroTech G77-7R page: 103 N s, 80.1 N average, 1.28 s |
| Color | white-yellow core at the nozzle, orange, then scarlet to crimson; AeroTech: Redline "produces a visible scarlet flame", photos do not do justice to its "laser-beam" intensity | aerotech-rocketry.com G77-7R (77707) product page; red from strontium salts (S. Jurvetson, steve.blog/2013/05/29/dairy-aire-night-launch) |
| Shape | narrow at the nozzle, widest about 40% down, pointed tail; no shock diamonds visible at this size | M1550 Redline liftoff photo, steve.blog/2008/12/08/redline ("red 8 ft. tall plume") |
| Size | nozzle exit not published: ~11 mm assumed, drawn 13 mm; outer sheath .40 m at 80 N (about 14 motor diameters, shorter than a scaled photo for the CAD look and the phone frame), core .105 m; length scales with sqrt(thrust) | judgment, noted in `flame.js` |
| Smoke | white to tan, pink only next to the flame ("cotton candy illuminated by the intensely bright red flame") | S. Jurvetson, scienceblogs.com/photosynthesis/2009/05/22/rocket-propellant-types |

The smoke trail is a flag (`#reel-smoke`): a 1/3-resolution 2D canvas (`.hero__smoke`) inside `.hero__stage` under the
drift words, masked off above the marquee; puffs grow, rise and are gone within 4 s.

## Motion rules for 3D

| Rule | Where |
|---|---|
| Reduced motion: the reel never starts; the hero draws one still frame (no intro, flame or smoke) | `index.js` `reducedQ` |
| Off screen or hidden tab: no frames | `index.js` IntersectionObserver + `visibilitychange` |
| Slow device (30th of 60 frame times over 38 ms): REST draws single frames on scroll | `index.js` `slow` |
| Guests pose everything as a pure function of reel time: `sample(T, states)`, no `dt` state | actor interface, `index.js` header |
| Modules never call `requestAnimationFrame`, add lights, fog or environments | `engine.js` header |
| Exploded views: staggered smootherstep arrivals in build order | `coaster.js` `setProgress`, `tools/cad/actor-adapter.js` |

House easings and durations: [motion.md](motion.md).

## CAD part name to showreel part name

```
STEP PRODUCT / instance name    tools/cad/maps/<model>.json rule     cadmesh part        actor
"Top Plate"                -->  {"match": "*plate*",           -->  name "topPlate"  --> getParts()[i].name === 'topPlate'
                                 "name": "topPlate"}                                     model.parts.topPlate (a Group)
                                                                                         PART_DIRS.topPlate in index.js
```

| Step | Rule |
|---|---|
| CAD name | the STEP PRODUCT name; repeated products use the instance name, else `product-1`, `product-2` (`M3x6 Screw-1`) |
| Match | map rules top to bottom, first match wins; globs, case-insensitive, tested on the CAD name, product name and path (`Assembly/Sub/Part`) |
| Name | the rule's `name` (camelCase). No rule: automatic (`07-fin-1` -> `fin1`, `BodyTube_Upper` -> `bodyTubeUpper`) |
| Many to one | rules with the same `name` merge into one part; each material stays its own mesh |
| Sub-objects | `"sub": "rotor"` makes a named child Group with its own pivot inside the part (`parts.blower.getObjectByName('rotor')`) |
| Build order | map `order`, else first rule per name |
| Explorer and hero ids | `"id": 18` keeps the id the explorer stories (`part-stories.js`) and `hero3d.js` materials expect |
| Labels | `label` for people (explorer list, viewer); never used as a key |

Fixed names today: Therma-Shift `shell, blower, board, heatsink, peltier, thermistor, topPlate, screws` (`coaster.js` `getParts()`, `index.js` `PART_DIRS`). Ready map: `tools/cad/maps/therma-shift.json`. Robo-Catcher and rudder pedals get their names from their actor's `PARTS` rows (`python3 tools/new.py actor ...`); write the map to match those rows.
