## Hard constraints
1. Plain HTML + CSS + JS (ES modules fine). No build step, no framework, no CDN dependency that the page cannot survive without. three.js is already vendored and may be imported via a relative path. Everything else: hand-written. (Over-engineered means we write the engine, not that we npm-install one.)
2. Must work when served statically from `/vx/` with relative asset paths (`../assets/...`). Also keep absolute `/vx/...` links valid for GitHub Pages.
3. Must not touch `support.js`/`_ds/` (the old page runtime). vx is standalone. May copy token values.
4. Accessibility and resilience are part of the craft, not an afterthought: keyboard reachable, real headings, alt text, `prefers-reduced-motion` honoured (decorative motion off, content still fully readable), no WebGL → still a complete, good-looking page, JS off → readable content. Mobile (390px) must be genuinely good, not just "not broken", including touch alternatives for pointer-driven effects.
5. Performance budget: adaptive. Measure frame time and degrade effect tiers automatically (this is itself a feature worth showing). Avoid loading all 73 MB of video; stream only what is near the viewport; prefer the alpha WebM where transparency matters.
6. No fabricated facts. Any number on the page must come from the content above or from the repo's pages. Decorative "telemetry" may be clearly labelled as live page instrumentation (fps, scroll velocity, viewport, time), never as fake rocket data.
7. Writing follows his voice rules (see above). No emoji. No exclamation marks.
