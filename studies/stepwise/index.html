STEP to web

STEP in.
Web out.

Stepwise turns a STEP assembly into a small binary and a JSON header that a web page loads in one call. Every part keeps its CAD name and gets its own pivot and explode vector.

$ npm i stepwise

02Quickstart

Inspect. Import. Load.

Three steps take a STEP file to a model in your page. They run here on the model in FIG 01. Pick another model there and the steps follow.

  1. 01Inspect

    List what the file holds

    inspect reads the assembly and prints every part with its CAD name and the name Stepwise suggests for it. It reports the unit, the size and the longest side, so you know if the file is Z up before you mesh it.

    Add --map-out and it writes a starter map with one rule per part.

    Terminal 
    $ stepwise inspect rudder-pedals.step

  2. 02Import

    Name the parts, then mesh

    A map file holds the choices. Rules match CAD names by glob, top to bottom, and the first match wins. Rules that share a name merge into one part.

    Flags override the map. --dry-run reads and meshes, prints the table and writes nothing.

    --up
    y z -z x -x -ySource up axis, turned to +Y
    --origin
    center bottom top keepWhere 0, 0, 0 goes
    --quality
    low medium highChordal deflection: .0008, .0003 or .00012 of the diagonal
    --explode
    1.0Part center minus assembly center, times this
    rudder-pedals.map.json
    Terminal 
    $ stepwise import rudder-pedals.step --map rudder-pedals.map.json

  3. 03Load

    One call in the page

    loadCadMesh fetches the two files and builds one Group per part, placed at its pivot. setProgress(p) moves every part along its explode vector: 0 is exploded, 1 is assembled.

    The loader has no imports. You pass it the three.js your page already uses.

03Docs

What you get

Keeps every part name

The STEP product name is the key. A rule maps it to the name your code uses, and model.parts holds the part under that name.

STEP name
Sensor lever
Map rule
{ "match": "Sensor lever", "name": "rocker" }
In the page
model.parts.rocker

An explode vector per part

Set it in millimeters with explode_mm. Leave it out and the part moves straight away from the assembly center.

Explode vectors stored in rudder-pedals.json, in meters
Partxyz
leverR0.0010.047-0.109
leverL-0.0020.0480.109
rodR-0.0650.035-0.070
rocker-0.048-0.0270.000

One small binary

Positions are 16 bit, normals 8 bit, indices 16 or 32 bit.

  • rudder-pedals.bin367 KB
  • robo-catcher.bin348 KB
  • charger-explorer.bin307 KB

Any unit, Y or Z up

Inch, meter or millimeter in. Meters and +Y up out. --up z turns (x, y, z) into (x, z, -y).

--up z

Repeated instances, one rule

M3x6 Screw-1 to -4 become one part with one glob. In the rudder pedals, eleven bearings, bolts and a pedal ride in leverR.

{ "match": "M3x6 Screw*", "name": "screws" }

A screenshot command that fails on console errors

shot opens the viewer in headless Chromium, saves the model assembled and exploded, and exits 1 on a console error or a failed request.
