## What changed

**Source and output layout**
- `index.html` moved to `src/index.html`. `build-case.py` now reads `src/index.html` and writes
  `src/projects/*.html`. Its `--check` diffs against `src/projects/`.
- `src/` mirrors the served tree. A template is written for its served location, so
  `build-case.py`'s path rewriting (`_ds/` to `../_ds/` and so on) did not need to change. The
  templates only work when served at `/index.html` and `/projects/x.html`. `tools/build.py --serve`
  does that for previews.
- The served `/index.html` and `/projects/*.html` are now static HTML, generated by
  `tools/prerender/prerender.js`.
- `tools/build.py` runs `build-case.py` and then the pre-render. `tools/build.py --check` runs
  `build-case.py --check`, renders into a temp dir and diffs against the committed pages.
  `--serve [port]` previews the templates.
- `README.md` (new, short) documents the owner workflow and the Node/Playwright/Chromium
  requirement. `tools/prerender/package.json` pins `playwright@1.56.1`, the version that
  rendered the committed output.

**Pre-render (`tools/prerender/prerender.js`)**
- Serves the repo on 127.0.0.1, with `/index.html` and `/projects/*.html` answered from
  `src/`. Every request to another origin is aborted, so the build never touches unpkg or Google.
- React and ReactDOM 18.3.1 UMD are vendored in `tools/prerender/vendor/` (sha384 matches the
  runtime's SRI) and loaded through `window.__resources`, which the runtime honors. That also
  turns off its `fetch(location.href)` re-fetch.
- Every script except `support.js`, `_ds_bundle.js` and React is answered with an empty body
  during the snapshot (critic C6). That covers site-palette, mobile-nav, media-playback,
  depth-motion, shader-bg, interaction-polish, photography-loader, the CHARGER integration,
  the walkthrough module, analytics-config, track and clarity. Nothing they do is baked in.
  `shader-bg.js` was not on the list, but it also mutates the DOM (it adds a canvas to #contact).
  The allowlist catches it, and it catches any island added later.
- The serialized page keeps every island `<script>` where the template had it, in order, with
  `defer`/`type=module`. `site-palette.js` is still the first element in `<head>`. Removed:
  `support.js`, the React tags, the `_ds_bundle.js` tag, the `text/x-dc` logic script, the
  runtime's `x-dc{display:none}` style, empty helmet styles and the `data-dc-tpl` editor attributes.
- Helmet stylesheets were already appended to `<head>` by the runtime, and stay in its cascade
  order. The runtime's base style (placeholder and print rules) moves from before `site-palette.js`
  to just before the first stylesheet. The cascade is unchanged, and `<meta charset>` stays within
  the first 1024 bytes.
- `tokens/fonts.css` is swapped for `css/fonts.css` in the same slot, with preloads for the two
  latin files. `_ds/.../styles.css` is dropped. It is nothing but `@import`s of the eight token
  files linked right before it, so no computed value changes, but it would have pulled Google
  Fonts back in. The script refuses to build if that file ever holds anything else.
- Three runtime details the snapshot has to carry by hand:
  1. The runtime turns `style-hover="..."` into an `insertRule`'d `.scpN:hover` class, which
     `outerHTML` does not show. Those rules are written out (the home page's Elsewhere links).
  2. React sets `muted` only as a property, so the attribute is restored on videos.
  3. A var() shorthand followed by a longhand serialized `border-bottom-width: ;` on the hero
     "Resume (PDF)" link. The resolved values are written instead. Any other empty longhand
     fails the build.
- The lucide icons (menu, linkedin, mail, arrow-down) are inlined as `data:` URIs of the vendored
  SVGs (`tools/prerender/vendor/lucide/`, ISC license). They are byte-identical to what unpkg
  served, so they render identically, and there are no icon requests. I kept them as `<img>`, not
  inline `<svg>`, because inline SVG with `filter: invert(1)` would rasterize differently.

**Fonts**
- `assets/fonts/*.woff2`: the exact files Google Fonts serves Chrome on Linux and Windows (the
  hinted Plex Mono build; macOS ignores hinting, so it renders the same there). Space Grotesk is one
  variable file per subset, declared at 300-700 as before. IBM Plex Mono keeps 400 and 500, the only
  weights any page renders. A computed-style sweep over all pages at 390 and 1440, including shadow
  roots, pseudo-elements, the open menu and the open palette, found Plex Mono 400 (all pages) and
  500 (404 only). All subsets are kept, so behaviour matches unicode-range exactly. OFL licenses
  are in `assets/fonts/`.
- `css/fonts.css`: the same `@font-face` rules with local URLs, plus the same `--font-*`
  properties as the token file. `_ds/` is untouched.
- Switched to it: `404.html` (absolute `/css/fonts.css`), `hi/index.html` (also dropped the
  Google preconnects, added a preload), `privacy.html`, `photography-lab.html`.

**Hover states (`css/static-interactions.css`)**
- Button (all five variants, plus the trailing arrow), NavLink color and underline, SocialRail
  background, and the ScrollCue arrow. The render tags these components with `data-ds-*`
  attributes through their own `...rest` spread. MediaFrame `hoverZoom` needs nothing, because
  `css/depth.css` already overrides it with `!important`, so React's scale(1.04) never showed.

**Other**
- `src/index.html`: `<html lang="en">` (a11y-4, partial). No heading levels changed.

## For the orchestrator

1. **websites.html** (owned by another agent) still links the token font file, which reaches
   Google Fonts. To finish the "no third-party origins" goal, apply this:

   ```html
   <!-- before -->
   <link rel="stylesheet" href="_ds/mert-t-reli-design-system-56763c60-2006-4913-8e27-d9c1c8053e6d/tokens/fonts.css">
   <!-- after -->
   <link rel="stylesheet" href="css/fonts.css">
   ```

   It should be zero-diff: websites renders Space Grotesk 400/500/600 and Plex Mono 400, all
   covered. Re-run visual-regress on it.
2. **Every later batch that touches index.html or the case pages** now edits `src/index.html` or
   `build-case.py`, then runs `python3 tools/build.py` and commits both. Snippets written against
   the old root `index.html` apply unchanged to `src/index.html`. The other agents' files keep
   working: the static pages load `js/track.js`, `js/clarity.js`, `js/mobile-nav.js`,
   `css/mobile.css`, `js/site-palette.js`, `css/site-palette.css`, `js/media-playback.js` and the
   charger explorer from the same tags and paths. A branch that edited root `index.html` or
   `projects/*.html` directly needs its edit ported to `src/` or `build-case.py` and a rebuild.
3. CSS that matches inline style text (css/mobile.css does) still works. The static pages carry
   the exact `style` strings the runtime produced.
